# M2 单材料最小纵向闭环验收记录

记录日期：2026-07-14

视觉复用复核：2026-07-15

## 1. 结论

M2 已形成单材料萃取的真实纵向闭环候选：玩家可选择并投入青岚草，手动装备凡火，使用鼠标控制喷火方向与火力，移动接液容器，烧完 64×64 材料成分图，接取药液珠并正常结束本炉；完成后可以建立全新会话再来一炉。

自动化和真实浏览器验收均未使用假数据跳转。2026-07-15 复核发现首版 M2 只复用了 M1 火流模拟，未复用 M1 已完成的连续火焰热场与水滴轮廓；该缺口现已修复并完成回归。随后根据用户反馈补上配置化快速出火，火焰不再首帧铺满整条路径，而是从底部喷口经过 `emerging` 快速进入稳定 `animated`。M2 暂保持“等待用户视觉确认”，不在用户确认前进入 M3；本记录也不提前宣称药渣、杂质、灼烧保护、争斗互动或蒸汽警告等 M3 规则已经完成。

## 2. 本轮交付

### 2.1 配置与素材

- 新增 M2 配置集、JSON Schema、Node/Browser loader、语义校验与规范化模型。
- 原型内容为 1 种材料“青岚草”、1 类药液珠和 1 种可用火源“凡火”；火源、库存、材料摆放、容器、珠子物理、火力初值和滚轮步长均来自配置。
- 青岚草总体积按 `targetPearlCount × standardPearlVolume = 8 × 1 = 8` 建立；成分图为 64×64，外观图为 512×512，并校验真实 PNG 解码、非空 alpha 和逐格轮廓对齐。
- 材料实例使用配置化中心、尺寸、每份偏移与每层旋转；当前原型允许有意的部分重叠，拒绝完全同位同角度和越界摆放。
- M2 启动内容指纹为 `c88cbe47e928f439419a0faeb616da82db7a7da45c77d909c4d7d473459d98e2`。

### 2.2 领域、应用与模拟

- 完成 Command → application transaction → SimulationDelta → DomainEvent → Phaser 的权威链路，失败 tick 不发布半成品状态。
- 实现材料预选、取消、投入，火种选择与装备，只装备不自动点火；未装备的按下不会潜伏到后续 tick。
- 实现局部暴露探测、旋转材料格求交、动态遮罩、解析圆与材料碰撞、扫掠子步防穿透、确定性产珠和下一 tick 才参与模拟的 newborn 语义。
- 完整珠与尾量珠统一走体积账本；溶解、出生、自然流失与终态在候选副本上原子提交。浮点容差以 256 ULP 覆盖 4096 格合法累计误差，同时拒绝有意义的超扣。
- 接液容器支持 A/D 加减速、轨道夹取和中心进入 AABB 才接取；发生几何夹取时立即清零越界速度。
- `canFinish` 同时要求 extracting、至少投入过材料、全部材料体积归零和活动珠为零。
- 暂停/恢复、窗口失焦与可见性、重开请求/取消/确认、完成后再来一炉均经 application control channel 串行处理；旧会话归档，新会话从独立基线开始。

### 2.3 玩家工作台

- M2 默认进入玩家工作台；M1 技术场景保留在 `?mode=technical`。
- 工作台提供火种、连续 0～100 火力滑条、配置化滚轮步长、背包、待投材料、暂停、重开和结束操作。
- 逻辑舞台保持 1600×900 等比缩放；输入按实际 Canvas 坐标换算，letterbox 区域不会触发喷火。
- 1920×1080 与 1366×768 完整可见；900/950px 窄屏切换为纵向滚动，列表刷新后保留键盘焦点。
- M1 的 `FirePresentation`、`FireHeatField` 和贝塞尔水滴轮廓已提取为共享表现组件；M1、M2 使用同一实现，M2 仅保留药液青配色。
- M2 由模拟 ReadView 发布权威有效火源，连续热场逐帧读取同一火流结果；材料遮罩通过图层精确遮蔽，活动珠使用羽化几何遮蔽。
- M2 使用共享火焰的 `rapid-reveal` 配置：预热载体保证稳定火焰质量，但密度、温度和火星只在推进前沿后显示；当前默认推进速度 `3000px/s`、软边 `70px`，约 0.15 秒抵达原型药材、0.4 秒内铺满当前方向可见路径。
- 正常模式每次按下都从喷口重新进入 `emerging`，松开、暂停或失焦立即清除；低动态模式跳过快速推进，直接显示稳定静态全火，避免火焰永久停在喷口。

## 4. 审查与修复闭环摘要

- application 审查修复 tick 最终化时机、输入释放、暂停丢步、只读归档和 seed/range 边界。
- simulation/config 边界清单覆盖外部配置、严格 JSON、图片解码、typed array 隔离、材料摆放、暴露求交、高速碰撞、容器四边和 reset 重放。
- UI/E2E 审查修复 Canvas/舞台坐标分离、窄屏滚动、M1 样式泄漏、焦点恢复、零库存状态和配置驱动的真实闭环。
- 视觉复用复核先以 RED 测试证明 M2 缺少有效火源和共享渲染器元数据，再提取共享火焰/水滴组件；全量回归额外发现纯几何配置误引 Phaser，拆分纯配置边界后恢复 Node 测试。
- 视觉边界复核继续以真实浏览器 probe 复现暂停后旧火焰仍推进、粗格遮挡挖空、低动态不重绘和测试配置保留 WebGL 帧缓冲；每项由新 repair 轮先落 RED，再最小修复，最终全新 reviewer 复跑六项边界后无阻塞发现。
- 快速出火复核实测修前首帧已有 92/280 个载体越过药材高度，最远距喷口约 696px；RED 单测与 E2E 固化前沿距离、远端透明、真实 wall delta、`emerging → animated` 和松开重按语义后再实现共享软前沿。
- 最终数值审查复现“大体积相对容差吞掉超扣”和“体积容差误用于几何夹取”；新 repair 轮先落 RED，再分别改为 256 ULP 体积语义与严格几何夹取。R9 复审未发现新的阻塞问题。

## 5. 已知非阻塞项

- production build 仍提示 Phaser 主 chunk 约 1.67 MB，大于 500 kB；当前启动、交互和回归均通过，暂不为消除提示提前引入分包复杂度。
- M2 当前只保证火焰可靠、连续、从喷口快速长出并能读出绕流，不代表最终艺术质量已完成。黄白焰心/橙色主体/暗红外缘的精修、局部光、余焰、完整音效、镜头反馈和全部状态特效按补强后的 M5 画面品质矩阵收口，并须再次取得用户视觉确认。
- M2 只验证单材料与药液珠闭环；药渣、杂质、保护时间、灼烧、珠子互动和蒸汽警告按实施计划留给 M3 及后续阶段。
- 本记录的验收边界为 M2 功能、画面、自动化与构建结果，不以工作树或远端分支状态作为验收证据。
