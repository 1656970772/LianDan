# M4 完整内容与配置验收记录

## 验收结论

M4“完整内容与配置”已完成并通过验收。正式网页原型现包含 8 种药材、8 个三维状态批次、47 个标签、16 张正式 PNG 素材、材料专属药液珠颜色，以及配置驱动的“赤寒相争”丹珠互动。

本次实现保持领域规则、配置加载、指纹输入、模拟运行时和 UI 展示之间的单向数据流；药材本征标签不被批次状态回写，丹珠从投入批次继承归一化标签。

## 标签与批次派生

- 本征标签分为药性、功效线索、反应特征、风险四类，每种药材每类至少 1 项。
- 批次状态由保存状态、来源和年份三轴配置派生，统一归入“批次状态”展示类别。
- 状态派生标签的 `strength` 由 `tags.json` 显式配置并受 Schema 的 0..100 范围约束，不再由代码写死。
- 每个正式批次最终得到 7 个标签：4 个本征标签和 3 个状态标签。
- 背包 Tips 同时支持鼠标悬停和键盘聚焦，展示五类标签、说明入口和强度条。
- 键盘聚焦会在背包内部自动滚动，使当前 Tips 完整落在可视区域内。

## 丹珠互动

`/config/m2/interactions.json` 定义 `red_frost_medicinal_fight`：赤须参药液珠与寒髓晶药液珠在 64 逻辑像素内触发“赤寒相争”。互动持续 0.6 秒，冲量 180，冷却 1.5 秒。

运行时使用确定性的空间哈希网格查询邻近丹珠，并按稳定 ID 排序解决配对；同一丹珠同一时刻最多参与一次互动。安全区只屏蔽火伤和火流障碍，不屏蔽丹珠互动。互动通过领域事件发布，并在画布上显示连线和火花反馈。

## 本轮复审收口

- Node 加载器、浏览器加载器和 `validate-assets` CLI 现在都会校验基础清单中全部已登记的外观图，包括未被 M2 库存引用的材料；损坏 PNG、空图和轮廓错位均保留精确错误码与像素路径。
- 浏览器端把外观图的请求/响应体读取异常统一报告为 `CONFIG_ASSET_NOT_FOUND`，只有取得字节后的 PNG 头、解码和轮廓校验才报告对应的素材格式问题。
- 正式发布目录已移除 `prototype-herb` 的材料配置、外观图和成分图 3 个孤儿文件，并由测试锁定清单与 8 份材料配置、8 张外观图、8 张成分图一一对应。
- 8 种药材的名称、批次状态、标签强度、素材路径和成分数据使用一张 8 行期望表逐项验收；8 个批次都通过同一套通用预选与投入门禁，不再只抽查单一批次。
- 火焰启动 E2E 改为在浏览器内用 `MutationObserver` 记录完整属性轨迹，再对渐进喷出过程断言，避免测试端轮询漏掉短暂中间帧。
