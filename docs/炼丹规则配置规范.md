# 炼丹规则配置规范

版本：1.0  
状态：当前实现依据

## 1. 目标

配置层负责描述“有什么”和“满足什么条件会发生什么”，规则引擎只实现有限、通用的计算能力。修改材料、丹药、效果、因素选项、阈值或权重时，不应修改 React 组件和规则主流程。

所有运行时配置必须是 JSON 兼容数据。网页开发期可以使用带 TypeScript `satisfies` 校验的配置模块，构建或迁移时必须能无损导出为标准 JSON。

## 2. 根配置

```ts
interface AlchemyConfig {
  schemaVersion: string
  configVersion: string
  meta: ConfigMeta
  tagDefinitions: TagDefinition[]
  materialStates: MaterialState[]
  materialOrigins: MaterialOrigin[]
  materialKindProfiles: MaterialKindProfile[]
  materials: MaterialDefinition[]
  factorGroups: FactorGroup[]
  factors: FactorDefinition[]
  optionCatalogs: OptionCatalog[]
  effects: EffectDefinition[]
  traits: TraitDefinition[]
  evaluations: EvaluationDefinition[]
  scoreModels: ScoreModels
  pillPrototypes: PillPrototype[]
  modifierRules: ModifierRule[]
  mutationRules: MutationRule[]
  failureResults: FailureResultDefinition[]
  presets: SimulationPreset[]
}
```

`schemaVersion` 表示数据结构兼容性，`configVersion` 表示规则和平衡内容版本。未来玩家存档版本不得复用这两个字段。

## 3. 稳定 ID

- 仅使用小写 ASCII、数字和下划线，例如 `material_huiling_chiguo`。
- ID 发布后不可因中文改名而改变。
- 各目录内部必须唯一；跨目录引用必须存在。
- 中文名称只作显示和导出说明，不参与判断。
- 原因码使用命名空间，例如 `identity.material.missing`、`quality.fusion.ideal`。

## 4. 标签配置

```ts
interface TagDefinition {
  id: string
  category: 'nature' | 'effect' | 'reaction' | 'risk' | 'state'
  name: string
  description: string
}

interface TagValue {
  tagId: string
  strength: number
}
```

标签强度必须是 0 至 100 的有限数。配置不得临时创建未登记标签。

## 5. 材料配置

```ts
interface MaterialDefinition {
  id: string
  name: string
  kind: 'herb' | 'flower' | 'fruit' | 'root' | 'core' | 'liquid' | 'wonder'
  description: string
  allowedStateIds: string[]
  allowedOriginIds: string[]
  defaultStateId: string
  defaultOriginId: string
  ageLabel: string
  ageUnit: string
  maturityLabel: string
  defaultYears: number
  yearRange: { min: number; mature: number; max: number }
  baseTags: TagValue[]
  doseValue: number
  icon: string
  sourceNote: string
}
```

材料状态和来源独立配置：

```ts
interface MaterialState {
  id: string
  name: string
  description: string
  tagMultipliers?: Record<string, number>
  tagDeltas?: Record<string, number>
  qualityDelta: number
  riskDelta: number
}

interface MaterialOrigin {
  id: string
  name: string
  description: string
  tagDeltas?: Record<string, number>
  qualityDelta: number
  riskDelta: number
}
```

类别上限同样属于根配置，而不是校验器硬编码：

```ts
interface MaterialKindProfile {
  id: 'herb' | 'flower' | 'fruit' | 'root' | 'core' | 'liquid' | 'wonder'
  allowedStateIds: string[]
  allowedOriginIds: string[]
  defaultStateId: string
  defaultOriginId: string
  ageLabel: string
  ageUnit: string
  maturityLabel: string
}
```

初版全局状态目录包含新鲜、干燥、冰封、衰败、完整、破损与封存；来源目录包含荒野、药圃、灵脉、妖兽与秘境。类别配置定义允许上限，每种材料再通过 `allowedStateIds` 和 `allowedOriginIds` 取其子集。UI 只展示材料允许值，配置校验和输入校验都必须拒绝跨类别值。

植物类默认使用“年份 / 成熟”，魔核使用“兽龄 / 凝核”，天地奇物使用“蕴化年限 / 圆满”，灵液使用“蕴生年限 / 药力圆满”。这些显示语义完全来自材料配置；新增类别内材料不修改材料行组件。魔核不得出现“新鲜、干燥、药圃”等植物专属语义。

## 6. 动态因素配置

```ts
interface FactorDefinition {
  id: string
  label: string
  groupId: string
  valueType: 'number' | 'string' | 'boolean'
  controlType: 'range' | 'select' | 'toggle' | 'number'
  defaultValue: number | string | boolean
  min?: number
  max?: number
  step?: number
  unit?: string
  options?: Array<{ value: string; label: string; description?: string }>
  optionCatalogId?: string
  description: string
  visibilityCondition?: Condition
}
```

校验规则：

- `range` 和 `number` 必须给出有限的 `min`、`max`、`step`，且默认值合法；
- `select` 必须有内联选项或 `optionCatalogId`，选项值唯一；
- `toggle` 的默认值必须为布尔值；
- 可见性条件只能引用更早或无依赖的因素，禁止循环；
- UI 负责按元数据渲染，业务规则不得写入控件组件。

## 7. 选项目录

丹炉、火种、炉况、环境和天象使用统一选项目录：

```ts
interface OptionCatalog {
  id: string
  name: string
  options: Array<{
    id: string
    name: string
    description: string
    icon?: string
    modifiers: Array<{
      target: 'danger' | 'formation' | 'quality' | 'tag'
      targetId?: string
      value: number
    }>
  }>
}
```

选项修正是有限数据，不允许嵌入表达式。

## 8. 效果、特质与评价目录

```ts
interface EffectDefinition {
  id: string
  name: string
  category: 'primary' | 'secondary' | 'side'
  description: string
  unit: string
  range: { min: number; max: number }
}

interface TraitDefinition {
  id: string
  name: string
  description: string
}

interface EvaluationDefinition {
  id: 'normal' | 'residual' | 'waste' | 'mutated'
  name: string
  description: string
}
```

毒性可以属于主功效或副作用，取决于正式丹药定义。毒丹命中正式原型时不自动获得 `waste`。

## 9. 条件表达式

```ts
type Condition =
  | { op: 'all'; conditions: Condition[] }
  | { op: 'any'; conditions: Condition[] }
  | { op: 'not'; condition: Condition }
  | { op: 'hasMaterial'; materialId: string }
  | { op: 'materialQuantity'; materialId: string; min?: number; max?: number }
  | { op: 'tagRange'; tagId: string; min?: number; max?: number }
  | { op: 'factorRange'; factorId: string; min?: number; max?: number }
  | { op: 'factorEquals'; factorId: string; value: string | boolean }
  | { op: 'materialState'; materialId: string; stateId: string }
  | { op: 'materialOrigin'; materialId: string; originId: string }
  | { op: 'orderBefore'; firstMaterialId: string; secondMaterialId: string }
  | { op: 'qualityRange'; min?: number; max?: number }
  | { op: 'dangerRange'; min?: number; max?: number }
  | { op: 'formationRange'; min?: number; max?: number }
```

每个叶子条件必须能生成结构化满足或未满足说明。`all` 和 `any` 只组织条件，不隐藏子条件。

## 10. 分数模型

```ts
interface WeightedFactor {
  source: 'factor' | 'material_quality' | 'option_modifier' | 'dose_fit'
  sourceId?: string
  weight: number
}

interface ScoreModel {
  base: number
  inputs: WeightedFactor[]
  min: number
  max: number
}

interface ScoreModels {
  danger: ScoreModel
  formation: ScoreModel
  quality: ScoreModel
  thresholds: {
    explosion: number
    formation: number
    qualities: Array<{ quality: string; min: number }>
  }
}
```

权重之和不强制等于 1，但配置校验应报告异常量级。分数最终限制在模型范围。每项贡献保留原因来源，供 UI 展示。

## 11. 丹药原型

```ts
interface PillPrototype {
  id: string
  name: string
  form: 'pill' | 'powder' | 'liquid'
  grade: number
  priority: number
  description: string
  icon: string
  identityCondition: Condition
  idealFactors: Array<{
    factorId: string
    idealMin: number
    idealMax: number
    penaltyPerStep: number
  }>
  yield: { dosePerPill: number; min: number; max: number }
  primaryEffect: EffectGrant
  secondaryEffects: EffectGrant[]
  sideEffects: EffectGrant[]
  traits: string[]
  sourceNote: string
}

interface EffectGrant {
  effectId: string
  value: number
}
```

优先级数值越大越优先。特异度由原型身份条件中的叶子条件数量计算，不由配置人员手填。

## 12. 结果修正与异变

```ts
interface ModifierRule {
  id: string
  name: string
  phase: 'danger' | 'formation' | 'quality' | 'result'
  priority: number
  condition: Condition
  actions: RuleAction[]
  reason: ReasonTemplate
}

type RuleAction =
  | { type: 'adjustDanger'; value: number }
  | { type: 'adjustFormation'; value: number }
  | { type: 'adjustQuality'; value: number }
  | { type: 'adjustYield'; value: number }
  | { type: 'grantEffect'; effectId: string; value: number }
  | { type: 'scaleEffect'; effectId: string; factor: number }
  | { type: 'grantTrait'; traitId: string }
  | { type: 'grantEvaluation'; evaluationId: string }

interface MutationRule {
  id: string
  name: string
  priority: number
  probability: number
  condition: Condition
  actions: RuleAction[]
  reason: ReasonTemplate
}
```

同一阶段内规则按 `priority` 降序、`id` 升序执行。产生互斥身份或互斥特质时必须由配置校验拒绝，不能依赖数组偶然顺序。

## 13. 预设

```ts
interface SimulationPreset {
  id: string
  name: string
  description: string
  input: SimulationInput
  expectation?: {
    status: string
    prototypeId?: string
    quality?: string
    evaluations?: string[]
  }
}
```

预设同时用于 UI 示例、单元测试和 Unity 对照。每个正式丹药至少有一个可达预设；每个主要失败分支至少有一个预设。

## 14. 初版内容范围

初版药材至少包含：墨叶莲、蛇涎果、聚灵草、水系二阶魔核、凝血草、活气果、罂粟花、生骨花、回灵赤果、血莲精、冰灵焰草、清体草、冰火融魂果、水灵莲子、寒髓枝和火灵根。

初版正式结果至少包含：聚气散、凝血散、回气丹、生骨丹、冰心丹、血莲丹、清魂丹和离火丹。可在不破坏可达性测试的前提下继续加入风行丹、龙力丹、解毒丹和龟息丹。

## 15. 启动校验

应用启动或测试时至少检查：

- 根结构和版本字段；
- ID 格式与重复；
- 全部引用存在；
- 每种材料的默认状态和来源都属于其允许列表；
- 材料允许列表不得超出对应 `materialKindProfiles` 的类别上限；
- 材料年龄标签、单位和成熟标签非空；
- 数值有限且范围合法；
- 默认因素值合法；
- 原型有主功效、图标和产量范围；
- 效果值不越过目录范围；
- 条件引用阶段合法；
- 品质阈值单调并覆盖 0 至 100；
- 高概率的同优先级身份冲突；
- 预设输入合法且期望可达。

错误信息包含配置路径和相关 ID，禁止静默使用默认内容。

## 16. Unity 迁移包

网页规则稳定后的迁移包包含：

- 标准化 UTF-8 JSON 配置；
- JSON Schema 或等价字段约束；
- 条件与动作操作符说明；
- 固定求值顺序和取整规则；
- 伪随机算法及种子规范；
- 原因码和中文模板目录；
- 预设输入输出 JSON；
- 确定性测试向量与期望哈希。

Unity 不复用 TypeScript 源码，而是依据同一配置语义和测试向量独立实现。
