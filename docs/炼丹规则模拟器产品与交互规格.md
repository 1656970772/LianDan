# 炼丹规则模拟器产品与交互规格

版本：1.0  
状态：当前实现依据  
更新时间：2026-08-12

## 1. 产品定位

炼丹规则模拟器是面向游戏策划、程序和数值设计人员的单页开发调试工具。它用于回答三个问题：

1. 当前药材与外部条件能否成丹；
2. 成为什么丹、品质与数量如何、会附带哪些功效和副作用；
3. 哪些规则和因素造成了上述结果，继续调整哪个参数最有效。

工具不承担最终玩家玩法、美术演出或操作手感验证。规则在网页端达到稳定、可解释、可复现后，再迁移到 Unity。

## 2. 明确不做

第一版不实现：

- 实时控火、火焰方向、按压蓄力或鼠标跟随；
- 药材局部溶解、流体、接液、药渣和丹珠物理；
- 萃取、融合、凝丹的逐阶段按钮、倒计时、动画或时间线；
- 炉压、纯度、危险度等计算结果的手工覆盖；
- 联机、账号、后端数据库和云端存档；
- 生成式 AI 命名或自由文本功效；
- 面向玩家的任务、成长、经济、背包和战斗系统。

“萃取纯度”“融合度”“凝丹契合”等仅是一次推演的输入快照，不代表页面存在中间过程。

## 3. 用户主流程

1. 从药材库选择一种或多种药材。
2. 调整每份材料的数量、类别合法状态、来源、年份或兽龄以及投料顺序。
3. 调整配置自动生成的炼制因素。
4. 选择或输入固定随机种子。
5. 点击“推演成丹”或按 `Ctrl + Enter`。
6. 查看最终领域结果和原因摘要。
7. 改变一个或多个因素后再次推演，对比结果。

参数变化后不自动重算。旧结果保留并标记“输入已改变，结果待重新推演”，避免用户误把旧结果当成新结果，也方便临时对照。

## 4. 页面信息架构

### 4.1 顶部栏

顶部栏包含：

- 产品名与当前配置版本；
- 测试预设选择；
- 当前种子；
- 导出本次输入和结果；
- 导入测试输入；
- 恢复默认。

导入导出使用与规则引擎一致的 JSON 输入输出结构。第一版无需保存到服务器。

### 4.2 材料面板

材料面板分为“药材库”和“本炉材料”。

药材库提供：

- 按名称搜索；
- 按关键标签快速识别；
- 药材图标、名称、简短定位和加入按钮；
- 已加入材料的禁用或数量提示。

本炉材料的每一行提供：

- 图标、名称和投料序号；
- 数量步进输入；
- 状态下拉选择，只出现该材料类别允许的选项；
- 来源下拉选择，只出现该材料类别允许的选项；
- 配置命名的年龄参数滑动条与数字输入，例如灵植“年份”、魔核“兽龄”、奇物“蕴化年限”；
- 上移、下移与移除；
- 可展开的固有标签和状态派生标签说明。

材料顺序必须能通过按钮操作，不能只依赖拖拽。重复投入同一种材料时，界面合并为一份并增加数量；数量默认影响产量，不重复累加同名标签强度。

类别语义必须同时作用于 UI 与引擎校验。例如魔核默认显示“完整、妖兽、兽龄”，不能使用植物的“新鲜、药圃、年份”；导入的旧快照若包含不适用组合，应显示明确诊断而不是静默替换。

### 4.3 炼制因素面板

因素控件由配置元数据生成，页面组件不得按具体因素 ID 编写专用业务逻辑。因素按以下领域分组：

- 炼药师：炼药师品阶、灵魂力、控火能力、丹方熟练度、真元储备；
- 火候工艺：炉温、温控稳定度、萃取纯度、融合度、凝丹契合、蕴养程度；
- 丹炉火种：丹炉、火种、炉况；
- 环境天时：炼制环境、天象；
- 异变与随机：是否允许异变、固定种子。

连续因素使用“滑动条 + 数字输入”组合，同时显示合法范围、步长、单位和帮助说明。选择因素只展示配置中定义的选项。单项恢复默认属于可选增强，整体恢复默认必须提供。

### 4.4 推演操作区

“推演成丹”是页面唯一主操作。无材料或输入越界时禁用，并显示首个可操作的修正提示。推演使用点击瞬间的不可变输入快照。

本地同步计算应直接返回，不显示假进度条。若未来切换到 Web Worker，才显示真实的忙碌状态。

### 4.5 结果面板

结果面板先给结论，再给依据。成功结果至少显示：

- 丹药图标、正式名称与形态；
- 品质：下品、中品、上品或极品；
- 数量；
- 评价：正常丹、残丹、废丹、异丹等；
- 主功效及强度；
- 次要功效及强度；
- 副作用及强度；
- 特殊特质；
- 是否发生受约束异变。

未成丹与炸炉也使用完整的领域结果卡，不显示成技术错误。

### 4.6 原因摘要

原因摘要不按时间顺序展开过程，只展示最终判定证据：

1. 身份判定：已满足的核心材料、标签和因素条件；
2. 品质原因：实际增减项、阈值与最终品质；
3. 结果来源：每个功效、副作用和特质对应的配置规则；
4. 候选分析：最接近但未命中的丹药及其关键缺失条件；
5. 失败原因：未成形、无有效身份、危险越界或配置冲突的决定性条件。

原因项使用稳定原因码与中文文本。色彩只作辅助，必须同时使用文字“满足”“未满足”“提升”“降低”等表述。

## 5. 页面状态

### 5.1 初始状态

默认加载“聚气散·标准成丹”预设，并展示尚未推演提示。预设只填入表单，不自动制造结果。

### 5.2 输入校验失败

控件附近显示中文错误，顶部或推演按钮附近显示错误摘要。常见错误包括：

- 未选择材料；
- 数量、年份或因素越界；
- 随机种子不是整数；
- 导入结构版本不兼容；
- 配置引用不存在。

### 5.3 正常领域结果

- 成丹：命中正式原型并生成完整结果；
- 残丹：成形但品质或稳定条件明显不足，仍保留有限功效；
- 废丹：成形但核心药性严重失衡，不作为有效丹药；
- 异丹：满足实际因果条件且受种子选择的特殊分支；
- 未成丹：没有形成稳定丹体；
- 炸炉：危险条件越过配置阈值。

评价可以组合，例如“上品 + 异丹”或“下品 + 残丹”。毒丹若命中正式丹药原型，仍属于成功成丹，不因毒性自动视为失败。

### 5.4 配置或执行错误

以下属于技术错误，必须与领域结果区分：

- 同优先级且同特异度的丹药规则同时命中；
- 配置 ID 重复、引用缺失或数值范围非法；
- 成功结果没有主功效；
- 出现 `NaN`、负数量或越界结果；
- 未捕获的规则执行异常。

技术错误卡应显示中文概要、相关配置 ID 和可复制的诊断信息。

## 6. 响应式与无障碍

- 宽度不小于 1280px：材料、因素、结果三栏；结果栏随页面滚动保持可见。
- 900px 至 1279px：材料与因素在左侧纵向排列，结果在右侧。
- 小于 900px：按材料、因素、结果自然纵向排列，主操作保持易于找到；不强制横向滚动。
- 所有输入有可见标签；因素分组使用 `fieldset` 与 `legend` 或等价语义。
- 结果标题使用 `aria-live="polite"` 宣告，推演后可聚焦到结果摘要。
- 交互目标不小于约 44px，键盘可以完成加入、排序、删除、调参和推演。
- 焦点样式清晰，支持 `prefers-reduced-motion`，结果不只依赖颜色表达。

## 7. 视觉方向

页面采用“规则开发工作台 + 克制的炼丹语义”：

- 深墨色工作台背景，暖灰文字，青玉色为唯一主强调色；危险状态使用低饱和朱砂色；
- 信息密度高但层级明确，避免营销首页、巨型标题、玻璃拟态和装饰性渐变；
- 药材与丹药图标采用统一的修仙古籍插画质感，但必须保证缩小后轮廓可辨；
- 数值使用等宽数字，正文优先系统中文字体；
- 不使用无意义动画。必要的状态变化应快速且遵守减少动态设置。

## 8. 产品验收

产品层面的完成标准：

- 用户无需查看或操作任何中间过程即可从输入得到完整结果；
- 普通新增因素通过配置即可出现在页面；
- 至少十二种药材、八种正式丹药和六个确定性预设可实际操作；
- 成功、未成丹、残丹、废丹、异丹和炸炉均可从预设或明确调参达到；
- 结果中的名称、效果、特质、数值和原因全部可追溯到配置 ID；
- 相同输入与种子重复运行结果完全一致；
- 桌面与窄屏均无关键控件遮挡、文字溢出或不可达操作。
