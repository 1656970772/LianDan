# 测试向量与验收标准

版本：1.0  
状态：当前实现依据

## 1. 测试策略

测试分为五层：

1. 配置校验：结构、范围、引用、冲突和结果完整性；
2. 规则单元测试：条件、随机、分数、身份、品质、产量和修正；
3. 确定性测试向量：完整输入到完整结果；
4. React 组件测试：配置控件、材料编辑、推演和结果状态；
5. 浏览器验收：真实页面主流程、响应式和关键无障碍行为。

每个缺陷修复应优先增加能复现该缺陷的最小测试。

## 2. 确定性约定

- 随机种子使用 32 位无符号整数语义，输入先规范化到该范围。
- 引擎使用项目内固定的伪随机算法，不使用 `Math.random()`。
- JSON 哈希前按稳定键顺序序列化。
- 数值中间量按 IEEE 754 双精度计算，写入结果前按字段约定取整。
- 分数保留一位小数，效果强度和数量使用整数。
- 条件列表、原因列表和候选列表排序稳定。

## 4. 配置正负例

### 4.1 正例

- 完整配置启动校验为零错误；
- 所有材料和丹药图标路径存在；
- 每个正式丹药至少有一个可达预设；
- 每个因素默认值在范围或选项目录内；
- 品质阈值按分数严格递增。

### 4.2 负例

至少覆盖：

- 重复材料 ID；
- 材料引用不存在标签；
- 原型引用不存在效果；
- 原型缺少主功效；
- 因素默认值越界；
- 下拉默认选项不存在；
- 条件引用不存在材料或因素；
- 概率小于 0 或大于 1；
- 品质阈值顺序错误；
- 产量最小值大于最大值；
- 同优先级、同特异度的原型对同一可达预设冲突。

错误信息必须给出配置路径或稳定 ID。

## 5. 规则不变量测试

- 同名标签默认取最大值，不求和；
- 增加同种材料数量默认不提高标签强度；
- 状态、来源和年份修正后标签仍在 0 至 100；
- 数量可以改变产量，但不在无声明时改变丹药身份；
- 危险达到阈值优先于成形和身份；
- 成形未达阈值不会产生正式丹药；
- 未命中正式原型时只进入配置化残丹或废丹；
- 身份冲突不会随机选择；
- 品质分在 0 至 100，品质阈值边界准确；
- 高品质仍可保留原型本身的副作用；
- 无因果候选时不会异变；
- 同种子异变结果一致，不同种子只能在合法候选内变化；
- 成功丹药数量为正整数且不超过配置上限；
- 成功丹药必有主功效和至少一条身份原因；
- 所有效果、特质和评价都能追溯到配置 ID。

## 6. 稳定性与边界测试

对关键连续因素执行边界附近测试：

- 在不跨越任何配置阈值时，将因素调整一个最小步长，身份保持不变；
- 在跨越成形、危险或品质阈值时，结果按文档定义切换；
- 输入最小值与最大值不产生 `NaN`、无穷大或负数量；
- 0 份材料、非法年份、非整数种子在执行前被拒绝；
- 大量合法材料不会导致明显卡顿或原因列表无限增长；
- 取整只在约定位置发生，Web 与 Unity 测试向量不依赖平台偶然行为。

## 7. 组件测试

至少验证：

- 默认预设正确填入材料与因素；
- 搜索药材可以过滤且清空后恢复；
- 加入、调整数量、状态、来源、年份、排序和移除材料；
- 滑动条与数字输入保持同步；
- 下拉、开关由配置渲染；
- 无材料时推演被阻止并显示原因；
- 点击按钮与 `Ctrl + Enter` 都能推演；
- 推演后显示正式结果和原因；
- 修改输入后旧结果显示过期；
- 切换预设清理旧结果；
- 导出包含输入、结果和配置版本；
- 未成丹与炸炉使用领域结果，不显示配置错误。

## 8. 浏览器验收

### 8.1 桌面主流程

在 1440×1000 视口：

1. 页面加载无控制台错误；
2. 选择聚气预设并推演；
3. 结果显示聚气散、品质、数量和原因；
4. 降低凝丹契合后显示结果过期；
5. 再次推演后品质或结果按阈值变化；
6. 切换炸炉预设并得到炸炉原因。

### 8.2 窄屏主流程

在 390×844 视口：

- 页面无整页横向滚动；
- 材料、因素和结果按自然顺序可达；
- 输入、选择与主按钮不重叠；
- 结果文本和图标不裁切；
- 键盘焦点可见。

### 8.3 无障碍快检

- 页面有唯一主标题；
- 所有表单控件有可访问名称；
- 按钮不使用无标签图标；
- 结果区域有可聚焦标题和礼貌宣告；
- 满足与未满足同时有文字；
- 缩放到 200% 时核心操作仍可完成。

## 9. 性能基线

在常规开发机、默认配置与不超过 20 份材料的情况下：

- 单次同步推演目标低于 50ms；
- 初始生产包保持为轻量单页，不引入与需求无关的大型依赖；
- 因素调整只更新必要 UI，不触发自动推演；
- 图片使用适合实际显示尺寸的 PNG，不加载原始大图集作为每个列表图标。

性能目标是开发体验约束，不以牺牲可读性或规则正确性为代价。

## 10. 最终验收清单

- [ ] 因素控件由配置元数据生成。
- [ ] 支持材料数量、状态、来源、年份和顺序。
- [ ] 成功结果字段完整。
- [ ] 成功、未成丹、残丹、废丹、异丹和炸炉均可达。
- [ ] 结果有身份、品质、修正和失败原因摘要。
- [ ] 相同配置、输入和种子结果一致。
- [ ] 不产生未配置名称、效果、特质或无界数值。
- [ ] 配置冲突明确失败。
- [ ] 修改普通配置无需修改 UI 组件。
- [ ] 正负配置测试通过。
- [ ] 引擎、组件和浏览器测试通过。
- [ ] 生产构建通过。
- [ ] 文档与最终实现一致。
