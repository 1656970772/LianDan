# 网页端炼丹规则模拟器实施计划

版本：1.0  
状态：执行中  
更新时间：2026-08-12

## 1. 实施目标

交付一个可在本地浏览器运行的完整炼丹规则模拟器。用户能选择药材、调整配置生成的因素、执行一次成丹推演，并查看不同丹药、品质、数量、功效、副作用、特质以及最终原因摘要。

完成不以“页面能打开”为标准，而以规则可控、主要结果可达、输入可复现、文档与测试一致为标准。

## 2. 成功标准

- 单页工作台包含材料、因素和结果三部分。
- 不存在实时炼制操作、过程动画或反应时间线。
- 所有普通因素由配置元数据动态生成。
- 规则引擎独立于 React，可用纯 TypeScript 调用。
- 至少 16 种材料、8 种正式丹药和 6 个结果预设可用。
- 相同输入、配置和种子重复执行结果一致。
- 所有正式结果和主要失败分支有结构化原因。
- 类型检查、配置校验、规则单测、组件测试、生产构建和浏览器主流程验收通过。
- 药材与丹药图标以正式 PNG 存入项目并在 UI 使用。

## 3. 技术选择

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 单页本地工具所需能力足够，启动与构建简单 |
| UI | React + TypeScript | 适合配置驱动的重复控件、材料数组和结果状态 |
| 状态 | React 本地状态 | 页面单一，无需引入全局状态库 |
| 样式 | 原生 CSS | 避免整套组件库限制高密度工作台布局 |
| 规则 | 纯 TypeScript 函数 | 与 UI 解耦，便于确定性测试和 Unity 对照 |
| 测试 | Vitest + Testing Library | 覆盖配置、引擎与组件交互 |
| 浏览器验收 | Playwright | 覆盖真实页面主流程与窄屏布局 |
| 图像 | AI 生成 PNG 图集后切分 | 保持统一修仙插画风格并减少视觉漂移 |

不引入 Phaser、物理引擎、路由框架、后端、Redux、表单框架、动画库或整套 UI 组件库。

## 6. 实施取舍

### 6.1 第一版不做高级派生值覆盖

危险度、纯度结论、炉压和药效保留率由输入推导。如果同时允许用户直接修改，会出现“破损丹炉、极高炉温但危险度为零”之类自相矛盾的案例。需要做引擎边界测试时，应在单元测试直接构造上下文，而不是污染普通 UI。

### 6.2 动态生成不采用自由组合命名

自由拼字可以快速产生大量看似不同的丹药，但不可控、不可测，也难以迁移。本项目只允许命中正式原型，再由修正规则改变次效、副作用、特质和参数。

### 6.3 不做自动平衡求解器

第一版通过预设和可达性测试保证主要内容可用，不实现搜索全部参数空间的自动平衡器。若后续丹药数量显著增加，再单独评估批量采样或约束求解工具。
