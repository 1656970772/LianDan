# M5 画面品质与灼烧表现验收记录

记录日期：2026-07-16

## 1. 验收结论

M5 已达到当前网页原型继续开发所需的画面与交互基线，用户确认不再继续打磨本阶段视觉细节，后续开发重点转向融合、凝丹环境和配置化成丹判定算法。

本阶段已经完成大尺寸药材、互不重叠的材料布局、沿真实受火前沿逐格缩小、从消失位置生成并脱离材料运动的三类丹珠，以及火焰、炉温、警告、失败、音频和无障碍表现。应用默认静音，玩家测试时可以自行开启声音。

## 2. 关键交付

### 2.1 药材与灼烧

- 正式药材可见长边为 170 逻辑像素。
- 24 个配置化槽位覆盖当前库存；权威内容 OBB 两两不发生内部相交，最小间距为 4 像素。
- 药材透明外框可以相交，但真实可见内容和碰撞区域不得相交。
- 灼烧不再把溶解量平均分摊到整排格子；同一份材料只保留一个正在续烧的未完成格。
- 火焰按照配置化 lane 和每条 lane 的第一接触格推进：小火形成深而窄的缺口，大火形成浅而宽的剥离。
- 火焰转向时先收口旧的 pending 格，避免留下多个由火造成的半透明格。
- 只有被火蚀操作本身清空的格才建立后续火道；自然损耗补完的格不会误导火焰穿透。
- 材料遮罩把剩余体积转换为单元内部的面积减少，药材轮廓随灼烧单调退让。

### 2.2 丹珠生成与运动

- 药液、药渣和杂质继续由 64×64 隐藏成分图的真实溶解位置产生。
- 首颗标准珠形成前，材料已经有完整格消失，不再出现“珠子先堆在药材上、药材外形不变”的情况。
- 标准珠出生点必须与全部剩余材料保持配置化间隙；找不到合法位置时整 tick 原子失败并可重放。
- 珠子与剩余材料碰撞时保留切向速度，只反射法向分量，避免药渣长期静止粘附在材料表面。
- 浮点累计使用统一体积容差，`0.9999999999999999` 个标准体积会在本 tick 正确形成一颗标准珠，不会延迟到下一 tick 一次补发两颗。

### 2.3 表现与运行边界

- M5 表现配置独立于模拟配置，纯视觉变化不改变 simulation fingerprint。
- 火焰、炉温、护盾、受伤、蒸汽、警告、失败转化、珠子特效和声音均走配置与对象池。
- 默认应用内静音；浏览器本身不永久静音，玩家可以在后续测试时自行打开声音。
- 当前验收浏览器为桌面 Chrome 横屏；不要求 Edge，也不配置竖屏浏览器验收。
- 24 份材料同时喷火不属于实际玩法负载，不作为本阶段性能门槛；24 槽静态不重叠仍保留为正式配置门禁。

## 4. 正式视觉证据边界

最后一次完整证据采集生成了 64 张 PNG，其中 60 项被捕获，4 项失败：

- `coverage/loss-warning-one`
- `coverage/loss-warning-two`
- `accessibility/grayscale/warning-one`
- `accessibility/grayscale/warning-two`

前两项的原因是 warning 流程仍使用材料移动前的旧瞄准点 `(600,285)`，没有灼烧到当前首材料；后两项是前述 60 秒超时造成的浏览器上下文级联关闭。玩法警告逻辑本身没有失败。

该缺口已经修正：

- warning 配置目标更新为 `(711,525)`；
- runner 按材料定义和库存批次读取实时 `contentPlacement.center`；
- 配置目标只作为 fail-closed 一致性断言；
- support 测试 99/99 通过；
- 真实 Chrome warning 定向测试 1/1 通过。

根据用户“当前视觉差不多即可，重点进入后续成丹环境与算法”的决定，本阶段不再重复运行整套 64 格采集。旧的 60/64 报告只作为问题定位记录，不作为玩法仍有四项失败的结论。

## 5. 下一阶段

下一阶段优先实现：

1. 萃取完成后进入融合与凝丹的场景环境；
2. 以玩家实际收集到的药液、药渣和杂质为唯一输入；
3. 通过配置化规则依次判定危险、成形、丹药核心条件、工艺分支、品质和受约束异变；
4. 生成配置定义的丹药名称、主功效、次要功效、副作用、特殊特质、品质和评价标签；
5. 保持固定随机种子下可重放，不用材料比例或硬编码材料组合直接决定丹药身份。
