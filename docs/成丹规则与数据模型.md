# 成丹规则与数据模型

版本：1.0  
状态：当前实现依据

## 1. 设计原则

规则系统遵守以下不变量：

1. `simulate(input, config)` 是无状态纯函数，不读取系统时间、DOM 或外部服务。
2. 相同配置版本、输入快照和随机种子产生完全相同的输出。
3. 丹药身份由明确的核心条件决定，不用一个模糊相似度直接任选名称。
4. 丹药结果采用“配置化原型 + 配置化修正规则”，动态但不失控。
5. 所有名称、效果、副作用、特质、评价、范围与中文解释来自配置目录。
6. 规则按固定阶段和显式优先级执行；不可消解的冲突作为配置错误。
7. 页面只接收最终结果和原因摘要，不渲染规则内部的阶段时间线。

## 2. 输入快照

一次推演输入包含：

```ts
interface SimulationInput {
  schemaVersion: string
  configVersion: string
  materials: MaterialInput[]
  factors: Record<string, number | string | boolean>
  seed: number
}

interface MaterialInput {
  materialId: string
  quantity: number
  stateId: string
  originId: string
  years: number
  order: number
}
```

输入在执行前完成结构、引用和范围校验，并规范化材料顺序。输入中的中文名称只用于显示，业务判断一律使用稳定 ID。

## 3. 材料与标签

### 3.1 材料字段

每种材料配置至少包含：

- `id`：稳定 ID；
- `name`：中文名称；
- `kind`：灵植、果实、花、根茎、灵液、魔核或天地奇物；
- `description`：小说语义说明；
- `baseYears` 与合法年份范围；
- `baseTags`：固有标签引用及强度；
- `icon`：正式 PNG 图标路径；
- `sourceNote`：素材来源或项目补全说明。

### 3.2 五类标签

标签强度统一限制在 0 至 100。

| 类别 | 作用 | 示例 |
| --- | --- | --- |
| 药性 `nature` | 阴阳、寒热、燥润等基础性质 | 寒、热、阴、阳、温和 |
| 功效线索 `effect` | 丹药身份与效果的主要线索 | 聚气、回气、止血、生骨、清魂 |
| 反应特性 `reaction` | 与火种、状态或其他材料的反应倾向 | 易挥发、难熔、亲水、冰火共生 |
| 风险 `risk` | 炸炉、副作用与失败风险 | 暴烈、毒性、寒髓反噬、灵魂冲击 |
| 状态 `state` | 由保存、来源、年份等派生 | 鲜活、干燥、冰封、衰败、药力丰沛 |

标签定义与材料引用分离。规则只依赖标签 ID，不依赖中文字符串。

### 3.3 标签聚合

- 同一种材料重复投入时，同名标签强度不相加。
- 不同材料提供同名标签时，默认取本炉有效强度中的最大值。
- 数量默认影响有效药量和产量，不提高标签强度。
- 只有显式的协同规则可以改变上述默认，例如“血莲精与冰灵焰草同炉时护体线索提高 12”。
- 所有派生值经过 `clamp(0, 100)`。

单份材料的有效标签强度按以下顺序计算：

1. 读取固有标签；
2. 应用保存状态的倍率或增减值；
3. 应用来源修正；
4. 应用年份分段修正；
5. 应用只针对该材料的显式规则；
6. 限制到 0 至 100。

年份不使用无限线性增长。每种材料通过配置给出成熟年份，达到成熟后收益显著递减，超过安全年份也可增加药性冲突或失控风险。

## 4. 可调因素

初版因素均为本次炼制的摘要输入：

- 炼药师品阶；
- 灵魂力；
- 控火能力；
- 丹方熟练度；
- 真元储备；
- 炉温；
- 温控稳定度；
- 萃取纯度；
- 融合度；
- 凝丹契合；
- 蕴养程度；
- 丹炉；
- 火种；
- 炉况；
- 环境；
- 天象；
- 是否允许异变；
- 固定种子。

炉压、综合危险、材料纯度和药效保留率属于派生结果，不在第一版直接编辑，避免产生逻辑互相矛盾的输入。

## 5. 受控动态丹药

### 5.1 丹药原型

丹药原型定义正式身份：

- 稳定 ID、名称、形态与图标；
- 身份优先级；
- 核心材料与最低剂量；
- 必需标签与因素范围；
- 禁止材料或排斥条件；
- 基础主功效、基础次要功效；
- 基础副作用与特殊特质；
- 品质理想区间；
- 单炉产量基准；
- 说明和来源。

原型条件全部满足才视为命中。可选材料和非核心偏差不得偷偷改变身份，只能通过明确修正规则改变效果或评价。

### 5.2 结果修正规则

修正规则可以：

- 调整品质分；
- 调整产量；
- 新增、移除或改变次要功效；
- 新增副作用；
- 新增特殊特质；
- 添加残丹、废丹或异丹评价；
- 产生结构化原因。

修正规则不能创建配置目录之外的名称或效果，也不能执行任意脚本。

## 6. 一次求值管线

规则内部固定按以下顺序执行，但界面不把它展示成过程时间线。

### 6.1 输入与配置校验

检查 Schema、范围、稳定 ID 引用、选项合法性、规则冲突和结果目录完整性。校验失败立即返回技术错误。

### 6.2 构建有效材料上下文

计算材料有效标签、总剂量、投料顺序特征、状态风险、来源与年份修正，并应用显式材料协同。

### 6.3 危险判定

危险分由配置化权重和危险规则组成，典型来源包括：

- 暴烈、毒性、极寒等风险标签；
- 炉温过高且温控稳定度不足；
- 火种强度超过丹炉承受范围；
- 炉况破损；
- 相斥材料或环境放大；
- 炼药师品阶、灵魂力与控火能力提供的抑制。

若危险分达到炸炉阈值，立即返回 `exploded`，并列出实际越界的决定性规则。危险分只用于危险分支，不直接替代身份判定。

### 6.4 成形判定

成形分由配置化权重组合以下可解释因素：

- 萃取纯度；
- 融合度；
- 凝丹契合；
- 温控稳定度；
- 灵魂力；
- 丹方熟练度与真元储备；
- 丹炉与炉况修正；
- 核心材料有效剂量；
- 明确的成形增益或减益规则。

低于成形阈值时返回 `not_formed`。不输出虚构丹药名，只显示药性散失、药浆、焦渣等配置化失败描述。

### 6.5 丹药身份判定

对全部原型执行核心条件检查，并为每个候选记录：

- 已满足条件；
- 未满足条件；
- 优先级与特异度；
- 与本次输入相关的关键缺失项。

选择规则：

1. 只从完全满足核心条件的候选中选择；
2. 优先级高者优先；
3. 优先级相同时，核心条件更多的原型具有更高特异度；
4. 优先级与特异度仍相同时，不静默任选，返回配置冲突。

若已经成形但没有正式原型命中，根据药性一致度和成形分进入配置化残丹或废丹分支。

### 6.6 品质判定

品质分限制为 0 至 100，由以下配置化项目组成：

- 通用工艺权重：萃取纯度、融合度、凝丹契合、温控稳定度、蕴养程度、灵魂力、丹方熟练度；
- 原型理想区间的偏差；
- 材料状态、年份和来源质量；
- 丹炉、火种与环境适配；
- 显式品质修正规则。

初版默认阈值：

| 品质 | 分数范围 |
| --- | --- |
| 下品 | 0 至 54 |
| 中品 | 55 至 69 |
| 上品 | 70 至 84 |
| 极品 | 85 至 100 |

阈值来自配置，不写死在 UI。规则解释必须给出真正的分数来源和关键偏差，不得在事后编造“综合匹配率”。

品质与副作用相互独立。高品质丹药仍可因配方本性带有副作用；低品质也不自动获得所有副作用。

### 6.7 产量

基础产量由有效核心剂量除以原型单位剂量得到，再应用丹炉容量、成形条件、品质档位与显式产量规则，最终取配置约定的整数范围。

数量不得为负，也不得超过原型或全局上限。投料数量只有在某条规则明确声明剂量阈值、过量风险或协同时，才可影响身份、功效或副作用。

### 6.8 功效、副作用与特质

先复制原型基础结果，再按优先级执行匹配的修正规则。相同效果使用稳定 ID 合并，数值限制在效果目录定义的上下限。每项结果保留 `sourceRuleIds`，用于原因面板追溯。

### 6.9 受约束异变

异变必须同时满足：

1. 用户允许异变；
2. 配置存在异变候选；
3. 本次材料、标签、火种、环境或天象确实满足该候选的因果条件；
4. 固定种子在配置概率范围内命中。

种子只在已满足因果的候选中选择，不允许凭空生成效果。无候选时，即使种子命中概率也不发生异变。

## 7. 规则条件 DSL

第一版只支持有限、可移植的声明式条件：

- `all`、`any`、`not`；
- `materialQuantity`：材料数量范围；
- `hasMaterial`：是否存在材料；
- `tagRange`：有效标签范围；
- `factorRange`：数值因素范围；
- `factorEquals`：选择或布尔因素相等；
- `materialState`、`materialOrigin`：指定材料属性；
- `orderBefore`：材料 A 是否早于材料 B；
- `qualityRange`、`dangerRange`、`formationRange`：只允许在对应后置阶段的修正规则中使用。

配置不得包含 JavaScript 字符串、表达式求值器或任意脚本。Web 与 Unity 分别实现同一组操作符。

## 8. 结果结构

```ts
interface SimulationResult {
  schemaVersion: string
  configVersion: string
  inputHash: string
  seed: number
  status: 'success' | 'not_formed' | 'exploded' | 'config_error'
  pill?: {
    prototypeId: string
    name: string
    form: string
    grade: number
    icon: string
    quality: 'lower' | 'middle' | 'upper' | 'supreme'
    qualityScore: number
    quantity: number
    evaluations: string[]
    primaryEffect: EffectResult
    secondaryEffects: EffectResult[]
    sideEffects: EffectResult[]
    traits: TraitResult[]
    mutated: boolean
  }
  metrics: {
    danger: number
    formation: number
    quality?: number
  }
  reasons: ReasonItem[]
  candidates: CandidateResult[]
  diagnostics: string[]
}
```

`EffectResult` 与 `TraitResult` 至少携带稳定 ID、中文名称、数值或等级、说明和来源规则 ID。

## 9. 原因模型

原因不是日志，而是结构化的最终证据：

```ts
interface ReasonItem {
  code: string
  phase: 'danger' | 'formation' | 'identity' | 'quality' | 'modifier'
  tone: 'positive' | 'negative' | 'neutral'
  title: string
  detail: string
  sourceId: string
  actual?: number | string | boolean
  expected?: string
  impact?: number
  relatedFactorId?: string
  relatedMaterialId?: string
}
```

同一原因码在相同上下文中必须使用一致中文模板。页面可以按阶段分组，但不得伪装成炼制时间顺序。

## 10. 结果不变量

- `success` 必须有正式或配置化兜底丹药对象、正整数数量和主功效。
- `not_formed` 与 `exploded` 不得伪造正式丹药对象。
- 所有效果强度、指标和标签均在各自范围内。
- 原因引用的材料、因素和规则必须存在。
- 候选列表最多展示配置数量上限，排序稳定。
- 不设置独立“稳定性”结果字段；需要表达稳定性时，用原因或特质。
- 丹纹不进入第一版结果结构。
- 任何随机分支都必须能由输入和种子复现。

## 11. 跨语言随机约定

初版使用 `xorshift32`。种子先转为 32 位无符号整数；若规范化后为 0，则替换为固定常量 `0x6d2b79f5`，避免零状态锁死。每次抽样只使用无符号整数运算，禁止 `Math.random()`。

随机不得决定丹药身份、危险分支、成形分支、品质档或数量，只能在满足因果的异变候选中进行概率判断，并对允许波动的效果参数做有限修正。所有抽样次序由规则优先级和稳定 ID 排序决定。
